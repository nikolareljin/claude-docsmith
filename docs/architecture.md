# Architecture

`claude-docsmith` is intentionally small. The skill defines the documentation policy; the Python package provides repeatable context gathering plus an optional Ollama fallback.

## Flow

1. The CLI receives a target repository path, an audience selection, and provider settings.
2. The scanner inspects common docs, config files, scripts, CI files, source trees, and tests.
   Supported image assets are inventoried separately, so binary content consumes neither
   text scan slots nor context bytes.
   Sensitive filenames are skipped outright; credential-shaped content in the files it does
   read is replaced with `[REDACTED:<kind>]` markers before anything is assembled.
3. For **each selected track**, the prompt builder embeds:
   - the `update-docs` skill
   - that track's reference (`references/user-manual.md` or `references/developer-reference.md`)
   - the screenshot capture reference and existing image inventory for the user track
   - that track's checklist
   - a JSON contract pinning output paths to that track's root
   - a compact repository inventory and excerpts from relevant files
4. Each track is generated by its own model call, so the two audiences do not share one
   output token budget. Claude Code can consume the prompts directly, or the CLI calls the
   Claude API (`--provider claude`) or a local Ollama server (`--provider ollama`).
5. The response parser expects structured JSON with file targets and contents. Results from
   both tracks are merged into one payload, each file tagged with the track that produced it.
6. The apply step writes documentation files only when `--apply` is set, rejecting any path
   outside the track's own root, re-scrubbing the content, and recording the result in
   `docs/.docsmith/manifest.json`.
7. `--check` re-scans the repository, compares source hashes against the manifest, and exits
   non-zero on drift. It makes no network request.

For Claude Code plugin usage, the plugin manifest in `.claude-plugin/plugin.json` identifies the plugin, while Claude Code loads the root-level `commands/` and `skills/` directories using the standard plugin directory layout.

## Modules

| Module | Responsibility |
|---|---|
| `audiences.py` | The two tracks: output root, skill reference, checklist, path allowlist, page-set contract |
| `scanner.py` | Bounded text scan plus safe image inventory; applies the sensitive-file deny list and inbound redaction |
| `redaction.py` | Sensitive-name deny list and credential pattern scrubbing; findings carry no values |
| `prompting.py` | Assembles one prompt per track |
| `providers.py` | Claude API and Ollama HTTP calls with retry |
| `models.py` | Snapshot and generation-result dataclasses; JSON parsing |
| `manifest.py` | `docs/.docsmith/manifest.json` read/write, source hashing, drift detection |
| `cli.py` | Flag parsing, track loop, path allowlist enforcement, apply, drift gate |

## Design choices

- Minimal dependencies: `httpx` for HTTP providers; no other runtime dependencies.
- One provider call per audience: a complete user manual and a complete developer
  reference cannot share a single response budget.
- Track-scoped output roots: a file may only be written inside the track that produced
  it, which is also what makes the two trees separately publishable.
- Defense in depth on secrets: scrub on the way in *and* on the way out, because the
  scanner reads a bounded file set while the model writes arbitrary paths.
- Offline drift detection: freshness must be checkable in CI without an API key.
- JSON output contract: easier to review and safer to apply than free-form prose.
- Read-first scanning: the model gets docs and code context together, so it can remove stale wording instead of only adding new text.
- Existing-doc preference: prompt instructions tell the model to update current docs before creating new files.
- Provider flexibility: Claude Code plugin (no API key needed), direct Claude API (`ANTHROPIC_API_KEY`), or local Ollama (`OLLAMA_BASE_URL`).

## Boundaries

- The tool does not mutate source code.
- The Python CLI does not run project-specific commands. The interactive skill may use
  approved project start commands and local capture tools for the user-documentation track.
- It does not infer undocumented behavior beyond code, config, tests, and existing docs.

## Future extensions

- Exporters: GitHub Pages (MkDocs Material), GitHub wiki, NotebookLM bundles

- Multi-turn repair when the first model response is not valid JSON
